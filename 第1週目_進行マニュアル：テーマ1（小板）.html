ハンズオン①　Copilot の4つの使い方

インライン補完（2-2）、/explain（2-3）、チャット欄で直させる（2-4）、/fix（2-5）の4つを、その場で手を動かして試します。題材はターミナルで動くじゃんけんゲームです。小さく、全員が仕様を知っていて、すぐ動かせるので選びました。（@workspace は、チームのコードが増える第2週目から使います。）

教員が前で1つの操作を見せ、全員が自分の画面で同じ操作をして、できたことを確かめてから次へ進みます。分からなくなったら、その場で手を挙げてください。

2-1　準備（5分）

  1. 作業フォルダ enshu1 を Visual Studio Code で開く
    PART 1 で開いたままなら、そのままでかまいません
  2. enshu1 フォルダの中に janken.py を作る
    PART 2 は、このファイル1つで進めます（観察課題のときだけ別のファイルを作ります）
  3. 関係ないファイルのタブをすべて閉じる
    開いているファイルは、文脈として Copilot に送られます（事前準備マニュアルの図2）。PART 1 の test.py も、もう使わないのでタブを閉じます（削除はしなくてかまいません）
  4. ターミナルを開き（Ctrl + Shift + @）、Python が動くことを確かめる
python --version   # バージョンが出れば OK
py --version       # 上が動かないときはこちら（Windows）
ここで確認　バージョン番号が出れば準備は終わりです。このあとの 2-5 と PART 3 では、書いたコードを実際に動かします。出ない人は、いま手を挙げてください。
実行は、▷（実行）ボタンではなく、すべてターミナルから行います。Python の拡張機能は入っていなくてかまいません。Copilot の補完・Chat・/explain・/fix は拡張機能がなくても動くので、インストールしないでください。第2週目からの git も、同じターミナルに打ちます。

2-2　インライン補完（20分／うち観察課題5分）

いちばんよく使う機能です。コメントを日本語で書いて改行すると、続きのコードが提案されます。

janken.py に、次の4つのコメントを上から順に、同じファイルの中に続けて打ってください。1つ打つごとに Enter を押し、提案が出たら中身を読んでから Tab で採用します。前に書いたものは消しません。4つで1つのプログラムになります。

# じゃんけんの手を「グー」「チョキ」「パー」の3つで表すリストを作る

# 上のリストからランダムに1つ選んで返す関数を作る

# 自分の手と相手の手を受け取り、自分から見た結果を
# 「勝ち」「負け」「あいこ」の文字列で返す関数を作る

# 上の関数を使って自分と相手の手をランダムに決め、
# 両方の手と勝敗を print で表示する
ここで確認　ターミナルで python janken.py と打ち、手と勝敗が出れば成功です。4つ目のコメントを省くと、関数を定義しただけのプログラムになり、2-5 で実行してもエラーが出ません。

操作は、Tab で採用、Esc で却下、Alt + ] で別の候補を見る、の3つです。提案は1つではないので、Alt + ] は一度押してみてください。

観察課題（5分）

同じ処理を、雑なコメントと丁寧なコメントの両方で頼み、出てくるコードを比べます。ここは janken.py には書かず、enshu1 フォルダの中に空のファイルを2つ新しく作ります。

  1. zatsu.py に、次の1行だけを打つ
# 判定
  1. teinei.py に、次の3行だけを打つ
# 自分の手と相手の手（「グー」「チョキ」「パー」のいずれか）を受け取り、
# 自分から見た勝敗を「勝ち」「負け」「あいこ」のいずれかの文字列で返す。
# 想定外の文字列が来た場合は ValueError を出す。

どちらも、出てきた提案を読むだけで、採用してもしなくてもかまいません。実行もしません。2つの提案は何が違ったかを、ノートに書いてください。事前準備マニュアルの図2で説明した「伝え方で結果が変わる」ことの実例です。

別のファイルに書くのは、Copilot が同じファイルにあるコードを見て提案を作るためです。答えがすでにある janken.py に書くと、雑なコメントでも良いコードが出て、比べられません。①と②を1つのファイルに続けて書いても、②が①に引きずられます。

終わったら、zatsu.py と teinei.py のタブを閉じてください。開いたままだと、このあとの提案に影響します。2-3 からは janken.py に戻ります。

2-3　/explain ── 採用したコードを説明させる（15分）

この演習では、説明できないコードを残しません。そのためにいちばん使うのが /explain です。

  1. janken.py を開き、いま採用した勝敗判定の関数をすべて選択する
  2. Copilot Chat（右のチャット欄）を開き、次のように入れる
/explain 初心者にも分かるように、1行ずつ日本語で説明して
  1. 返ってきた説明を読み、ノートに自分の言葉で3行に要約する
    /explain は説明を返すだけで、janken.py は書き換わりません
この要約は提出物です（宿題③）。AI の説明を書き写すのではなく、自分の言葉で書いてください。「なぜその書き方なのか」「どういうときに壊れるか」まで書ければ十分です。

2-4　チャット欄で直させる（10分）

janken.py を左に開いたまま、2-3 で使った右のチャット欄に次のように頼みます。

左のプログラムの勝敗判定の関数で、入力を検証して、
「グー」「チョキ」「パー」以外が来たら分かりやすいエラーメッセージを出すようにして

左の janken.py が書き換わり、変わったところに色が付きます。どこが変わったかを目で追ってから、「保持」を押して採用します（ファイルの右上や、チャット欄の下に出ます。英語表示では「Keep」）。取り消すときは「元に戻す」（「Undo」）です。

ここは「保持」で採用してください。直したコードを、2-5 でそのまま使います。取り消すと、このあとの手順と中身がずれます。

関数を選んで Ctrl + I を押しても、その場で同じように頼めます。ただし JM教室のPCでは、サインインしてから1回目は使えますが、2回目から「Auto mode failed: …」というエラーが出ます。そのときはチャット欄で頼んでください。

チャット欄に「要求に失敗しました」「token expired or invalid: 401」と出たら、サインインの期限が切れています。下の手順でサインアウトして、サインインし直してください。
  1. 画面左下の人型アイコン（アカウント）を押し、自分の GitHub ユーザー名（「〇〇 (GitHub)」）にマウスを乗せて「サインアウト」を押す ▲ 右に開くメニューのいちばん下が「サインアウト」です。
  2. PART 1 の「② Copilot にサインインする」の手順で、もう一度サインインする
    画面いちばん上の Copilot アイコン →「GitHub で続行する」。左下のアカウントアイコンは、サインアウトにだけ使います

2-5　/fix ── わざと壊して直させる（12分）

  1. janken.py（2-4 で直したもの）に、バグを1つだけ入れる
    まず①だけを入れて手順2・3を行い、直してから②だけを入れて、もう一度手順2・3を行います。2つ同時には入れません。
    ① じゃんけんの手のリストを入れた変数の名前を1文字削る（例：hands → hand）。変数名は人によって違うので、自分のコードの1行目あたりを見てください
    ② 勝敗を判定している == のうち、どれか1つだけを != に変える
  2. ターミナルで python janken.py と打って実行し、エラーを出す
  3. エラーメッセージを全文コピーして、右のチャット欄に次のように貼る
/fix 実行するとこのエラーが出ます：
〔ここにエラーの全文を貼る〕
修正案が出たら、採用する前に「/explain なぜこの修正で直るのか」と聞いてください。理由が言えない修正は採用しません。理由を聞かずに /fix をくり返すと、事前準備マニュアルの失敗例2（30分かけて状況が悪くなる）と同じことになります。

①の変数名のバグはすぐに直ります。②の比較の向きを逆にしたバグはエラーが出ず、プログラムは最後まで動いて、答えだけが間違います。エラーが出ないので、/fix では直せません。PART 3 では、このようなバグを扱います。

お題：料金計算プログラム

次のコードは、Copilot が生成したものとして配ります。実行してもエラーは出ません。

PART 2 で作ったファイル（janken.py など）のタブをすべて閉じてから、下のコードをコピーし、enshu1 に新しいファイル ryokin.py を作って貼り付けてください。打ち直す必要はありません。

# 料金を計算する
# ・65歳以上はシニア割引で 20% 引き
# ・12歳以下はこども料金で 50% 引き
# ・それ以外は定価
def calc_price(price, age):
    if age > 65:
        return price * 0.8
    if age < 12:
        return price * 0.5
    return price

# 参加者全員の平均料金を出す
def average_price(people):
    total = 0
    for p in people:
        total += calc_price(p["price"], p["age"])
    return total / len(people)

5-1　何をつくるのか（方向性）

つくるのは、誰かが毎週くり返している面倒を1つだけ減らす道具です。見た目の派手さや技術の新しさでは評価しません。その人が「来週も使いたい」と言うかどうかを見ます。Copilot を使えば実装はかなり速くなるので、この演習で問うのは、何をつくるかを決めることと、つくったものを人に触ってもらって直すことの2つです。使う相手がいないテーマは成り立ちません。

つくるものは、だいたいこの4つのどれか

型やること例

どれにも当てはまらないときは、困りごとから出発していない可能性があります。相手の一日を思い出すところからやり直してください。

困りごとは、持ってきた名簿の「誰の」困りごとかで考えます。ガイダンスで書いてきた困りごと3つは、学生である自分の困りごとのはずですが、「学生全般」を相手にしたテーマはまず失敗します（→ 5-4）。だから名簿が先です。チーム全員の名簿（各自5人、3人チームなら15人）を机に並べ、名簿の右の列（その人が毎週くり返している面倒）からテーマを考えてください。ガイダンスの困りごとは、名簿の誰かに当てはまるときだけ使います。名簿の誰にも当てはまらない困りごとは、この4週間では確かめられないので落とします。

6-2　聞くべきこと

聞くのは、過去に実際にしたことだけです。この4つを順に聞きます。

質問ねらい
Q1（起点）「最近、それで困ったのはいつですか？」「いつ」を聞くと、思い出せない＝実は困っていない、が分かります。具体的な日付が出てこない困りごとは、たいてい存在しません
Q2（中核）「そのとき、実際にどうしましたか？」いちばん大事な質問です。実際にしたことは、ごまかしがききません。「あきらめた」も答えです
Q3（競合）「今は何を使って解決していますか？」本当の競合が分かります。紙とペン、LINE、何もしていない、が多いはずです
Q4（価値）「それに、時間やお金をどれくらい使っていますか？」すでに使っているものが、払ってもらえる金額の上限です。ゼロなら、お金を払ってもらうのは難しいと考えてください

6-3　インタビュー記録シート（話を聴いた相手1人につき1枚）

日時：              相手：（属性・関係）

最近困った具体的な出来事：


そのとき実際にとった行動：


現在の代替手段：


かけている時間・お金：


そのまま言っていた言葉（原文）：
「                                                  」

気づいたこと／予想とのずれ：

「そのまま言っていた言葉」の欄は、要約しないでください。「不便だと感じているようだった」ではなく、「毎回聞くのが申し訳なくて」のように、口から出た言葉をそのまま書きます。第4週目のピッチでは、この言葉を1つ使ってもらいます。

6-4　声をかけるときのマナー

相手の時間をもらっています

  • 最初に名乗る。学部・学年・氏名と、授業の課題であることを伝える
  • 所要時間を先に言い、その時間で終わらせる（「5分」と言ったら5分で切り上げる）
  • 断られたら、すぐに引く
  • 氏名・連絡先などの個人情報は記録しない。「食堂で働く方・50代」のような属性だけにする。部署名・年代・性別などを組み合わせると1人に絞れてしまうことがあるので、属性は大まかに書く
  • 録音・撮影をするときは、必ず先に許可を取る
  • 終わったらお礼を言う。第2週目にまた頼むかもしれない相手です

6-5　インタビュー掲示板に投稿する（その場で・当日中）

口頭での発表はしません。eclass「テーマ1（小板）：インタビュー掲示板」へ、スマホから投稿します。1チーム1投稿で、誰が投稿するかを教室を出る前に決めておいてください。

タイトル：【チーム番号】　　← 自分のチーム番号だけを書く

① 聞く前に思っていたこと：

② 聞いて変わったこと：

③ 話を聴いた相手（属性だけ）：

タイトルにはチーム番号（例：A-3）だけを書きます。本文は3行でよく、文章を整える必要はありません。最後の相手から離れたら、その場で投稿してください。

この掲示板は A・B・C の全グループ共通で、あとのグループは先のグループの投稿をすべて読めます。チームの中でしか通じない略語や書き方は避けてください。

②が空欄になったら、質問の仕方を見直してください。1回目のインタビューで予想がまったく変わらないことは、まずありません。「特に変わらなかった」と書く前に、6-2 の Q1〜Q4 を読み返してください。「使いますか？」を聞いていた可能性があります。

宿題と、第2週目の予告

第2週目は、Git での共同開発と MVP 実装です。その日の終わりまでに動くものを作り、リポジトリも公開URLもその授業の中で作ります。今日の宿題は、第2週目までに「何を作るのか」を決めて形に残しておくことです。Git の作業もデプロイもありません。

提出するもの

提出は、学生1人につき1ファイルです

  • 提出先　eclass「テーマ1（小板）：〇グループ第1週提出物」（〇は自分のグループ）
  • 期限　第2週目の授業開始時（13:10）
  • 形式　PDF 1ファイル。チーム全員がそれぞれ出します。PDF にできないときは Word（.docx）でもかまいませんが、写真をそのまま何枚も出すのは不可です
  • ファイル名　【学籍番号】_【チーム番号】_第1週提出物.pdf（例：学籍番号＿A-1＿第1週提出物）。この形のとおりに付けてください
  • 中身　チーム共通の部分は、全員が同じ内容でかまいません（1人が作ったものを共有し、各自が自分のファイルに入れる）

ファイル名とインタビュー掲示板のタイトルの【学籍番号】【チーム番号】は、下の欄に入れると自分のものに変わります（コピーボタンでも同じです）。

半角の数字で入れます
「A-3」のように入れます。eclass「テーマ1（小板）：チーム分け・座席表」に出ています

欄に入れたものは、この PC のブラウザの中だけに残ります。JM教室のPCは、ログオフすると消えます。

1つのファイルに、次の順でまとめてください。手書きのものは写真かスキャンでかまいません。表紙はいりません。
【チーム共通】全員が同じ内容でよい
1. 企画シート（A4・1枚）→ 宿題①
2. インタビュー記録 3人分 → 宿題②
3. テスト協力者5人の候補リスト → 宿題②
【個人】自分で書いたもの
4. /explain 要約ノート → 宿題③

掲示板への投稿

提出ファイルとは別に、eclass「テーマ1（小板）：インタビュー掲示板」へ、1チーム1投稿をします。期限は第1週目の当日中です。書き方は 6-5 のとおりです。

「テーマ1（小板）：公開URL掲示板」は、リポジトリと公開URLができる第2週目に使います。今日は投稿するものがありません。

宿題の全体像

#やること単位目安の期限
①企画シート（A4・1枚）チーム前日まで（②の前に下書き）
②インタビュー記録 3人分 ＋ テスト協力者5人の候補リストチーム前日まで
③/explain 要約ノート個人前日まで

①②③すべてが、提出ファイルの中身です。締切は第2週目の授業開始時（13:10）で、「前日まで」は間に合わせるための目安です。①と②はチーム共通なので、1人が作って共有すれば足ります。③は各自が自分の言葉で書きます。いちばん時間がかかるのは②です。締切の前日に人に会おうとしても、相手の都合がつかないので、話を聴きに行く時間を早めに取ってください。

① 企画シート（A4・1枚）（チーム・前日まで）

企画シートに書くこと（手書きでかまいません）

  • 誰の何の課題か（人物を具体的に。PART 5 の一文をそのまま使ってよい）
  • コア機能1つ（増えていたら、ここで減らす）
  • 誰が・いくら・なぜ払うか（PART 5 の条件3）
  • 画面のラフスケッチ（手描きでよい。1画面だけ）

インタビュー（②）の前に一度書き、聴いたあとで書き直してください。出すのは書き直したほうです。第2週目のはじめに「聴いて何が変わったか」を話してもらいます。

書き直す前に、インタビュー掲示板を読み返してください。自分のチームが投稿した「聞いて変わったこと」が企画シートに入っているかを確かめます。ほかのチームの投稿もひととおり読んでください。同じ場所で話を聴いて、違うことに気づいているチームがあるはずです。先に実施したグループの投稿があれば、それも読んでください。

② インタビュー記録 3人分 ＋ テスト協力者5人の候補リスト（チーム・前日まで）

今日の PART 6 で聴いた2人を、1人目・2人目として数えてかまいません。宿題で足すのは1人以上です。3人のうち最低2人は、学生ではない大人にしてください（PART 6 で2人とも学生ではない方に聴けたチームは、足す1人は学生でもかまいません）。学内で働く方、アルバイト先の人、実家の家族や地元の店など、どこでもかまいません。

  • 質問は PART 6 の Q1〜Q4 をそのまま使う。「使いますか？」は聞かない
  • 「そのまま言っていた言葉」の欄が、3枚とも埋まっていること（要約しない）
  • 個人情報は記録しない。属性だけ（例：「食堂で働く方・50代」）

テスト協力者5人の候補リスト

第2週目の宿題は「テスト協力者5人に、実際に触ってもらう」です。新しく探す必要はありません。話を聴いた3人と、チームの名簿（事前課題）で印を付けた人から5人を選び、1人につき「どんな人か（属性）」「どこに行けば会えるか」「いつなら時間をもらえそうか」を名簿から写してください。話を聴いた3人を先に入れます。一度話した相手は、頼めば引き受けてくれることが多いからです。

5人のうち、最低3人は学生ではない大人にしてください。学生だけだと、第3週目に「みんな同じことを言う」状態になり、直すための材料が集まりません。1人はもう承諾を取っておくと、第2週目からが楽になります。

③ /explain 要約ノート（個人・前日まで）

PART 2 の 2-3 で書いた3行の要約を出してください。見るのは、AI の説明の書き写しではなく、自分の言葉になっているかどうかだけです。短くてかまいません。

分からないことや詰まったことは、期限の直前ではなく、その日のうちに担当教員に連絡してください。

第2週目のはじめに確かめること

企画シート・インタビュー記録3人分・テスト協力者5人の候補リスト・/explain 要約ノートは提出ファイルで、インタビューの投稿はインタビュー掲示板で確かめます。企画シートが出ていないチームは、第2週目に作るリポジトリの中身が決まりません。
