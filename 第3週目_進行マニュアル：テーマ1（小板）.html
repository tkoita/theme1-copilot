  • 1人が、自分の担当の Issue を1つずつ直します。2つ持っている人は、1つ目をマージしてから2つ目に取りかかります。
  • 2つの Issue が同じファイルを直すことになったら、同時に書き換えません。片方をマージしてから、もう片方を始めます（2人で同じ場所を書き換えると、第2週目の 2-4 で練習したコンフリクトが起きます）。
  • 手が空いた人は、ほかの人の Pull Request を読んでマージする役に回ります。

3-2　1つの Issue を直す手順

例は #1 を直す場合です。番号は、自分が直す Issue の番号に置き換えてください。ブランチ名は「自分の名字-fix＋Issue の番号」にします（#1 なら 【名字】-fix1。スペースは入れず、1つの名前です）。

★ コマンドの【名字】は、自分の名字に変えて打ちます（1-1 の欄と同じです。どちらに入れても、両方に入ります）

まだ入っていません。コマンドの【名字】は、自分で書き換えて打ちます。

① 最新を取り、ブランチを作る

git switch main
git pull
git switch -c 【名字】-fix1
git branch

最後の git branch で、* 【名字】-fix1 のように、自分のブランチに * が付いていることを確かめます。

② 直す場所を Copilot に探させてから、直す

  1. 画面いちばん上の Copilot アイコンを押してチャットを開き、Issue の本文をそのまま貼って、次のように聞く
    いきなり「直して」と頼まないのがコツです。まず場所を探させ、直し方の候補を出させてから選ぶと、関係のない場所まで書き換えられずに済みます
@workspace この指摘を直すには、どのファイルのどこを変えればよいですか。直し方を3つ挙げてください
  1. チームで1つ選び、そのファイルを開いて Ctrl + I で頼む
    例：「登録したら、一覧の上に『登録しました』と2秒だけ表示して」。書き足されたところを読んでから、右上の ✓ で採用します
  2. Ctrl + S で保存し、ブラウザで確かめる
    確かめ方は第2週目の 3-3 と同じです。Issue に書いた「詰まった場面」を、自分でやってみて、詰まらなくなったかを見ます

③ 送る（送る前に、必ず git branch）

git branch

* が 【名字】-fix1 に付いていることを確かめてから、次を打ちます。git add には直したファイルの名前を書きます（2つなら git add app.js style.css のように並べます）。push のあとに書くブランチ名は、* が付いている名前と1文字も違わないようにします。

git add app.js
git commit -m "登録したことが分かるようにする（#1）"
git push -u origin 【名字】-fix1

④ Pull Request の本文に「closes #番号」と書いて、マージしてもらう

  1. ターミナルに出た https://github.com/…/pull/new/【名字】-fix1 を、Ctrl を押しながらクリックして開く
  2. 本文の欄に、次の1行を書く
    番号は、直した Issue の番号にします。#2 を直したなら closes #2 です
closes #1
  1. 「Create pull request」を押す
  2. 自分以外のメンバーが Files changed で中身を読み、Merge pull request → Confirm merge を押す

★「最後にまとめてマージ」はしないでください。まとめるほどコンフリクトが重なり、直すのに時間を取られます。1つ直したら、すぐ Pull Request → マージです。
